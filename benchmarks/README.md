# BVT Benchmark Suite

EP7 evaluates whether datasets generated by Blender Visual Toolkit
transfer to real-world object detection.

The benchmark is deliberately separated from the BVT generator.

BVT creates reproducible datasets.

The benchmark trains and evaluates an external object detector on
those frozen datasets.

## Stress policy

The BVT `stress` preset is evaluation-only.

It must never be included in a core training arm.

This prevents the robustness benchmark from leaking into training.

## Real-world dataset

The real-world dataset must contain physical counterparts of the same
eight synthetic SKU classes.

Preferred acquisition:

```text id="5xz7jv"
synthetic BVT artwork
→ printed labels / wrappers
→ physical cans / bottles / cartons / boxes
→ real refrigerator or shelf
→ real camera photographs
```

This preserves class identity while avoiding commercial trademarks.

Splits are grouped by capture session to reduce leakage.

## Research rule

`real_test` is frozen before model comparison.

It is not used for:

- training;
- hyperparameter tuning;
- augmentation tuning;
- checkpoint selection.

### Controlled Artifact Engine ablation

Benchmark Clean is not the public deterministic `clean` showcase
preset.

For training research, Clean keeps the same placement, camera and
lighting randomization as the benchmark Artifact profile.

The controlled difference is Artifact Engine.

This prevents the ablation from being confounded by camera, lighting
or placement diversity.

## Dataset acceptance layers

Benchmark dataset verification uses two layers.

### Generation-time audit

The generation checkpoint operates on the actual dataset directory and
archive.

It verifies:

- images;
- labels;
- split membership;
- validation;
- health;
- hash manifest;
- archive hash;
- duplicate images.

The resulting immutable evidence is stored in:

```text
benchmarks/pilot-datasets-v0.1.json
benchmarks/publication-datasets-v0.1.json
```

### Repository regression

Repository regression validates the committed evidence records and
their source configuration hashes.

It intentionally does not require `.tmp` dataset archives.

`.tmp` is ephemeral and may be removed by unrelated smoke-test cleanup.

A missing `.tmp` archive therefore does not invalidate previously
recorded benchmark evidence.
